# Reusable Project Documentation Instructions

These instructions apply to this folder and its descendants. Complete the
dynamic project profile before work begins.

## Governing Files

Read and obey, in order:

1. `00_PROJECT_PROFILE.md`;
2. `03_PROJECT_WRITING_STANDARD_TEMPLATE.md` after it is customised and locked;
3. `05_RESEARCH_EVIDENCE_AND_CITATION_STANDARD.md`;
4. `07_PROJECT_EVIDENCE_AND_TRACEABILITY_STANDARD.md`; and
5. any official institutional template supplied by the owner.

The institutional template overrides conflicting presentation requirements;
all non-conflicting evidence, research, integrity, and traceability rules remain
binding.

## Mandatory Behaviour

- Inspect authentic project evidence before writing.
- Never transfer facts or results from another project.
- Work one engineering phase and one chapter at a time unless the owner changes
  the sequence explicitly.
- Do not progress past an approval gate silently.
- Preserve the approved scope, aim, objectives, questions, terminology, and
  validation boundaries.
- Never fabricate citations, data, participants, tests, results, screenshots,
  features, approvals, deployments, or validations.
- Maintain the source register, master references, objective traceability, test
  register, and phase-completion record as work proceeds.
- Keep research notes separate from approved chapter files.
- Maintain only one current file per chapter.
- Describe other algorithms/systems as literature comparisons unless they were
  genuinely implemented and verified in this project.
- Use sanitised evidence and never expose secrets or real sensitive data.
- Update documentation when implementation changes.
- Run the relevant tests and quality gate before claiming completion.
- At final compilation, filter references, remove duplicates and uncited items,
  retain unique cited entries, and alphabetise them.

## Source of Truth

Use executable tests, machine-readable reports, current code/configuration,
controlled interface inspection, and current documentation—in that order.
Investigate discrepancies and report them rather than selecting a convenient
answer.

## Change Control

Once the project profile and writing standard are approved, change them only
with explicit owner authorisation or a mandatory institutional requirement.
Record every approved revision.
